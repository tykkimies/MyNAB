# Review of the 0.3.0 implementation

Reviewed from commit `f245877`, with a clean worktree, after the owner requested review
of Claude's continuation. The manual ledger, immutable corrections, provider abstraction,
explicit start boundary, secret encryption, and release tooling are useful foundations.
However, passing tests did not establish that incremental bank ingestion was safe.

## Findings addressed by 0.3.1

| Severity      | Finding at review baseline                                                                                                                                                        | Resolution / regression evidence                                                                                                                                  |
| ------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Critical      | `planIngestion` treated absence from the current delta as removal. The next empty sync could reverse all known imported transactions.                                             | Only explicit `removed` IDs withdraw observations. Empty and partial deltas preserve history.                                                                     |
| Critical      | Planner transfer proposals displaced create decisions; application skipped proposals and still committed the cursor. Both transfer legs could disappear permanently.              | Persist posted entries independently; suggestions never suppress ingestion. Explicit merge reverses the two originals and creates one balanced transfer.          |
| High          | Pending observations were posted as uncleared transactions, changing working balances and RTA.                                                                                    | Nullable observation-to-ledger link; new pending entries have no ledger effects. Same-batch pending/posted and promotion/removal tested.                          |
| High          | `syncingSince` was read and set under READ COMMITTED, allowing simultaneous claims. Expired requests had no ownership token and could clear a newer claim or revive a disconnect. | Serializable budget locking, random lease token, cursor/token checks on commit, and conditional cleanup. Disconnect invalidates the lease before HTTP revocation. |
| High          | Bank updates/removals called `voidTransaction(..., true)` without owner acknowledgment and replaced category choices.                                                             | Persist bank-change review with an identity/version. Owner chooses apply or keep; reconciled corrections require acknowledgment.                                  |
| High          | No manual candidates were loaded and no match decisions could be completed.                                                                                                       | Explicit manual-match/transfer review UI, fresh validation at acceptance, remembered declines, audited reversals, and retry-safe resolved states.                 |
| High          | A newly linked second account could miss history already passed by the connection cursor; an existing link could be reassigned over imported history.                             | Replay from null after adding a link; identity deduplication plus start boundary prevents duplicates. Existing mappings cannot be reassigned.                     |
| Medium        | Manual corrections left provider identity pointing to the voided transaction.                                                                                                     | Repoint identity to the replacement; retained bank metadata preserves owner overrides. Reject moving bank-linked legs to unrelated accounts.                      |
| Medium        | Pagination mutation errors did not restart all pages.                                                                                                                             | Bounded restart from the original cursor; tests discard the interrupted batch.                                                                                    |
| Medium        | Provider endpoint read an unbounded body before checking its length.                                                                                                              | Streaming byte limit before parsing.                                                                                                                              |
| Medium        | Unknown currency was assumed USD; oversized floating-point values could lose cents.                                                                                               | Refuse unknown currency and unsafe cent magnitudes; no silent rounding.                                                                                           |
| Medium        | Token exchange happened before membership authorization.                                                                                                                          | Authorize first; revoke a newly exchanged token if account discovery/persistence fails.                                                                           |
| Documentation | README and specification retained obsolete Phase 1/2 status, while handoff called all Phase 5 complete.                                                                           | Refresh current status and separate verified implementation from outstanding scope.                                                                               |

Plaid's primary documentation confirms that sync responses are incremental patches and
pagination mutations require restarting from the original cursor:
https://plaid.com/docs/transactions/sync-migration/ . Pending removal and posted addition
can occur on different pages: https://plaid.com/docs/transactions/transactions-data/ .

## Production impact check

On 2026-09-23, a read-only SQL transaction against the deployed database returned zero
IngestedEntry rows, zero pending entries, and zero financial transactions reversed with
the old sync's removal/update reasons. No financial amounts, payees, tokens, or credentials
were retrieved. The running image was 0.3.0. No production data or deployment was changed.

The patch cannot automatically reconstruct observations skipped by an old cursor or restore
arbitrarily corrupted history. If an installation has such history, inspect its immutable
journals against institution records before repair. Do not blindly recreate openings or
replay old imports. The migration marks legacy pending ledger entries for explicit review;
it never silently reverses accepted financial records.

## Remaining work / review limits

- Goals/debt (Phase 3) still planned, not implemented. Finish the ingestion repair release first.
- Reauthentication/update-mode Plaid Link, OAuth redirects, worker jobs, webhook handling,
  durable fetch-batch staging and scheduled retries are not implemented. Sync remains an
  explicit bounded request; interrupted fetching does not advance the cursor.
- Bank corrections of a matched transfer require correcting both legs in the register,
  then keeping that corrected ledger entry in review. Automatic partial transfer rewrites
  would destroy the relationship between the two accounts.
- Import review lists the newest 200 observations; the register and match search still load
  history in memory. Pagination, indexed matching and larger-dataset performance are needed.
- Start-date linking defaults to the opening date; there is no date picker yet.
- Refund attribution still uses an ID. Safari/Firefox and assistive-technology review remain.
- No live provider requests were made in this review. Real PNC outflow sign and the first
  post-upgrade live sync still need owner verification. Offline adapter fixtures cover signs.
